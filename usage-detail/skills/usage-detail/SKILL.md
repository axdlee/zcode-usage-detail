# ZCode 用量明细查询

数据源是 ZCode 客户端本地 SQLite（默认 `~/.zcode/cli/db/db.sqlite`，可用环境变量 `ZCODE_USAGE_DB` 覆盖）的 `model_usage` 表：每次模型请求一行，含时间、所属会话、模型、输入/生成/缓存读 token、耗时与状态。套餐服务端配额（5 小时池/周额度）不在此库中，需引导用户查看 ZCode 的 Usage Stats → Coding Plan。

## 查询方法

运行本插件自带脚本。对本技能文件所在目录而言，脚本位于 `../../scripts/usage.sh`；若 `${ZCODE_PLUGIN_ROOT}` 可展开，也可写成 `bash "${ZCODE_PLUGIN_ROOT}/scripts/usage.sh"`。

```bash
bash "<本技能目录>/../../scripts/usage.sh" <子命令> [参数]
```

子命令与用户意图的映射：

| 子命令 | 用途 | 用户说法示例 |
|---|---|---|
| `dashboard <输出.html>` | 生成交互式仪表盘（HTML 片段） | "界面看看"、"仪表盘"、"图形化" |
| `summary` | 总览：累计 + 今日（默认） | "我的用量怎么样" |
| `providers` | 按来源汇总（官方套餐 / 自定义接入） | "官方套餐和 API Key 各用了多少" |
| `blocks` | 5 小时窗口用量（末尾窗口若在 5h 内即进行中） | "这个 5 小时周期用了多少" |
| `months` | 按月汇总 | "这个月用了多少" |
| `projects [N]` | 按项目目录汇总 Top N（默认 15） | "哪个项目最烧 token" |
| `tools [N]` | 工具调用统计 Top N（默认 15） | "最常用的工具是什么" |
| `cost` | 成本估算（默认内置 models.dev 官方价，~/.zcode/usage-prices.json 可覆盖/扩展） | "估算一下花了多少钱" |
| `prices [show\|sync]` | 查看价格表 / 从 models.dev 同步官方价 | "更新一下官方价格" |
| `live [秒]` | 终端实时燃烧率监控（默认 3s 刷新）。**只在用户明确要实时监控且在终端运行时使用，不要在会话里执行（会一直阻塞）** | "帮我盯着燃烧率" |
| `serve [端口]` | 本地常驻面板（默认 7741，浏览器打开、5s 轮询实时燃烧率）。用户要"常驻看板/实时面板/浏览器打开"时使用：以后台方式启动（run_in_background），把 http://127.0.0.1:7741 以 Markdown 链接交付，并说明仅监听本机、停止方式 | "我要一个常驻的用量看板" |
| `export csv\|json [路径]` | 导出全部记录 | "导出成 CSV" |
| `recent [N]` | 最近 N 条逐条明细（默认 20） | "看每条记录"、"最近 50 条" |
| `day [YYYY-MM-DD]` | 某天逐条明细（缺省今天） | "今天用了多少"、"看 10 月 14 日的" |
| `days [N]` | 最近 N 天按天汇总（默认 14） | "最近一周每天的用量" |
| `sessions [N]` | 按会话用量 Top N（默认 15） | "哪个会话最烧 token" |
| `models` | 按模型汇总 | "各模型的 token 分布" |
| `errors [N]` | 最近 N 条失败请求（默认 10） | "有没有报错的请求" |

## 仪表盘界面（dashboard）

用户想以界面/图表形式查看用量时使用：

1. 从宿主上下文找到本次会话的可视化输出目录（形如 `~/.zcode/v2/visualizations/<id>`，必须写入该目录），执行：

   ```bash
   bash "<本技能目录>/../../scripts/usage.sh" dashboard "<可视化目录>/usage-dashboard.html" [条数]
   ```

   条数控制内嵌的最近请求行数（默认 3000，范围 1-20000，可用环境变量 ZCODE_USAGE_LIMIT 覆盖默认值）。超过约 8000 条可能超出会话内嵌渲染的体积限制，更大的历史请改用 `export json`。

2. 在**最终回复**中单独一行输出内容引用（不要放进代码块），宿主会将片段内嵌渲染：

   ```text
   ::visualize{"path":"<可视化目录>/usage-dashboard.html"}
   ```

3. 仪表盘数据在生成时已内嵌，界面含总览/每日趋势/5小时窗口/会话排行/请求明细/失败请求六个标签页，无网络请求。
4. 若界面元信息显示"已加载 X / Y 条"且 Y 明显大于 X，主动告知用户：可指定更大条数重新生成，或用 `export json` 导出全量。
5. 若宿主未提供会话可视化目录，退化为普通交付：把生成的文件绝对路径作为 Markdown 链接告知用户，用浏览器打开。
6. 生成的界面是快照；用户要最新数据时重新执行 dashboard 覆盖同一文件，并在最终回复再次引用。

## 输出要求

- 只读操作：不写库、不修改文件、不发起网络请求。
- 结果用中文表格转述；用户要更多逐条记录时加大 N 即可，不要一次性倾倒全部历史。
- token 口径：输入列已含缓存命中（缓存读单独一列展示），生成 = 输出 + 思考。
- 数据库不存在或无法读取时如实报告原因，不要伪造数据。
